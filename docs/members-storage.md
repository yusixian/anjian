# 成员与存储管理

本文描述成员与存储版本的使用方式；实际发布状态见 [交付记录](DELIVERY_GOAL.md)。真实外部 S3 需要由管理员或成员提供配置并完成连接测试。

## 邀请朋友

1. 管理员使用已配置的 GitHub 账号登录，打开「存储设置 → 实例共享」，设置共享总容量。
2. 打开「成员管理」，点击「邀请朋友」，填写朋友的 GitHub 用户名和共享容量额度。
3. 复制本次生成的邀请链接发给该朋友。链接绑定指定 GitHub 账号，有有效期，接受后不能再次用于新增成员；可在成员管理中撤销未接受的邀请。
4. 朋友通过链接登录后获得独立空间，只能访问自己的作品与设备。公开分享链接仍可供匿名访客只读观看。

成员额度是实例共享容量内的个人上限，不是额外分配的物理空间。管理员可修改额度或暂停访问。暂停会使原会话失效；恢复访问后需要重新登录，不会自动恢复原登录会话。

## 配置 S3

管理员可在「实例共享」配置公共存储，成员在自己的「存储设置」配置个人 S3。填写 Endpoint、Bucket、Region、对象前缀及专用访问凭据。使用公开 HTTPS 地址；不支持私网地址或自签证书。需要兼容路径式寻址的服务，可勾选「使用路径式寻址」。

保存凭据后页面不回显。修改配置后需要重新测试连接；测试会写入一个小对象、读回校验并删除它。若清理失败，页面会显示需要手动清理的测试对象名称。不要把保存成功当成连接成功，也不要把连接成功当成已切换存储。

## 迁移与启用

1. 保存配置并通过连接测试。
2. 点击「准备迁移」，等待任务列出来源。
3. 点击「复制并校验」。复制失败时当前存储不切换，原文件保留；按页面提示继续复制或重新准备。
4. 校验通过后，勾选「启用此 S3，并保留服务器原文件」，再点击「启用 S3」。启用前会再次核对来源；来源变化时需要重新准备。

启用后页面显示「S3（服务器缓存）」。作品仍通过服务器缓存提供访问，运行期同步到所选 S3；启用个人 S3 的空间不再消耗实例共享额度。原文件不会自动删除，请勿自行清空服务器数据卷。

同步失败时本地修改保留，可以重试。重启后若出现待恢复提示，先检查服务器保留文件，再按页面确认以这些文件为准并校验恢复；不能用空目录替代缺失来源。恢复失败时保留现场，不要删除存储绑定记录或把未恢复的空间当成新空间初始化。

## 容量与备份边界

- 页面用量按受管理文件内容统计，包含历史、协作状态、回收站及分享快照；不是磁盘剩余空间或 S3 服务商余额。应用额度不是提供方的硬配额。
- S3 中为校验和恢复保留的对象，以及服务器缓存、临时处理空间和实例元数据，仍可能占用额外物理容量。应同时监控服务器磁盘和 S3 服务商用量；本版本不自动回收这些原始文件或保留对象。
- 额度不足时新增保存可能被拒绝。浏览器提示未保存时，不要关闭或刷新编辑页；先释放可释放的资源或增加额度，再确认保存完成。
- 成员、邀请、配置、加密凭据及存储绑定等实例元数据仍在服务器持久化目录；配置 S3 不会自动创建云数据库或备份这些元数据。使用仓库 Compose 部署时应备份整个 `/data` 数据卷，并保护备份中的凭据材料。
- 公开分享发布的是快照，草稿修改不会自动公开。发布新版本还需要容纳新快照的可用额度。

# 成员与存储实施记录

目标：管理员通过网页邀请 GitHub 成员、分配共享存储额度；成员使用独立个人空间，并可在网页配置自己的私有 S3。既有 Owner、作品、设备和公开分享保持兼容。此文档记录实施状态，不代表功能已上线。

## 当前证据与顺序

2026-11-10 审计：GitHub OAuth 只接纳 Owner；`hub.ts` 将身份折叠为布尔授权，作品列表、回收站、分享、设备批准与服务控制共用它。`route()` 按 URL/Referer/首个项目选挂载，挂载使用全局服务器密钥。`routes/content.ts` 的随机 `/c/` 路径和独立预览域名不校验成员。直接放开 OAuth 会让成员继承管理员权限，因此邀请登录须在全部入口隔离后启用。

1. **身份和归属。** 持久化 GitHub ID、邀请、成员状态、会话版本和项目归属；旧项目和旧设备默认属于 Owner。GitHub 用户名只用于显示，鉴权绑定不可变的数字 ID。邀请 token 仅保存哈希，绑定账号、到期、单次使用；暂停后旧会话不能在恢复时复活。
2. **完整访问边界。** 将 Owner、Member、Device 作为明确身份。所有 HTTP、WebSocket、源文件、预览、历史、下载、回收站、分享操作都按项目归属检查。服务控制、全局日志和实例设置仅 Owner 可用。成员不能收到全局密钥、磁盘路径或他人设备信息。成员暂停后既有 WebSocket 与设备也失效。
3. **GUI 成员流程。** 邀请、受邀账号核对、加入、个人空间、额度修改、暂停与恢复。CLI 配对只展示和批准本人项目。注册成员空间不能接受任意磁盘路径。
4. **存储适配。** 保留文件系统后端，为资源和发布快照接入私有 S3。先盘点文档/画板源文件、资源、历史、回收站与快照的读写生命周期，避免只上传新文件而遗漏已有读取路径。服务器仍保有必要元数据；GUI 明确 S3 容量不等于数据库或中转配额。
5. **GUI 存储与额度。** Owner 配共享 endpoint、bucket、region、凭据、总预算与成员额度；成员仅能配自己的凭据。凭据服务端加密，响应只给掩码；连接测试验证真实读写删除权限并清理测试对象。自定义 endpoint 防 SSRF、重定向与 DNS 重绑定。未配置真实凭据时显示待配置，不声称已接入。
6. **额度和迁移。** 并发写入先预留额度，失败释放，成功结算；纳入快照与回收站保留数据。迁移有持久进度、校验、失败重试和中断恢复，校验后切换读取。旧文件保留，清理单独确认；不能把迁移失败当成功或重复计费。

## 必须验证的交付边界

- 两个成员、Owner、设备、匿名访客交叉访问矩阵，包括猜测 URL、Referer、项目参数、`/c/` 源文件、独立预览域名、WebSocket 与已建立连接。
- Owner 原会话、旧项目/设备及原公开链接兼容；成员禁用后访问立即失效。
- S3 自定义 endpoint、凭据掩码/加密、失败诊断；使用受控兼容服务验证适配，真实外部 bucket 配置另行验证。
- 并发上传额度、覆盖/删除/回收站/分享计费、迁移断点和重试一致性。
- GUI 桌面/手机配置、邀请与错误状态的真实浏览器验收；提交、CI、部署与生产验证分别记录。

## 存储读写接入清单

- `remote-api.ts` 在项目锁内调用 `writeRemoteArtifact` / `readRemoteArtifact`；这是远程 CLI 上传/拉取入口，但不是全部写入入口。
- `routes/content.ts` 直接读取作品目录、历史资产与录制文件；S3 切换必须覆盖这些读取以及独立预览域名。
- 文档协作通过 mounted `settleDocument` 落盘，评论和画板操作也有独立持久化路径；不能只在 CLI 上传后同步 S3。
- `artifact-trash.ts` 的移入/恢复/清理以及 `share-store.ts` 的发布快照都产生保留资源，须纳入用量与迁移。
- 当前配置只作为待验证草稿，现有本地数据和公开分享快照均未移动。后续需要为迁移记录固定配置版本、对象清单与校验结果，通过校验后才切换读取。

## S3 切换接入前的约束

- 当前物化文件目录仍是同步读取模型：Hub 启动时先恢复回收站、建立分享与作品索引，挂载时打开文档。必须在这些步骤前恢复需要的本地读取内容，避免源文件缺失时启动空文档历史；仅将上传复制到 S3 不算接入完成。
- `withProjectMutation` 只覆盖远程上传和回收站。文档 HTTP 更新先修改会话、随后自动保存；评论同步落盘；录屏处理及其他 `.state` 更新也绕过该锁。迁移切换需停止准入、排空会话和录屏作业，并复核外部文件写入及完整根目录集合。迁移引擎只检查传入的根目录；新增项目或新增快照须由调用方在切换前重新盘点，不能遗漏。
- 资源清单不能直接复用 `readRemoteArtifact`：其排除隐藏身份文件、评论、历史和回收站。公开快照位于服务器 home，另行按归属纳入；元数据与凭据仍留在服务器。
- 迁移根目录和排除项只能由可信服务端构建，不接受浏览器路径。`artifacts/.state/server-info` 包含带全局 key 的 URL，`.state/.last-token` 也可能保留旧凭据；这些文件及其运行时临时副本必须排除，端口文件等运行信息也不应上传。源规划器已生成带 kind/owner 的可信根，扫描策略按资源类型持续排除运行态密钥与临时文件；其接入 HTTP/GUI 时仍须使用可信登记表，不能接受客户端路径。
- 活动映射及失败恢复核心已具备，但 Hub 尚未调用。必须在索引/文档枚举前恢复已提交内容，遇到 pendingScopes/冲突或提供方失败时保持该数据范围不可写，并在管理界面提供修复入口，不能照常打开空文档。
- checkpoint 已支持完整 scope 或单一逻辑成员的完整根集合；调用时必须保持相应写入屏障并重验完整来源集合。不可传入单个项目冒充该成员所有根，否则会移除同成员其他根的活动引用。恢复返回成员归属，调用方应通过 `summary(scope, owner)` 判断成员状态，不能用共享汇总 pending 冻结所有成员。
- 用量展示的 5 秒缓存不能用于额度准入；原文件保留与本地缓存也不能被当成两份用户资源重复扣费。intent、历史元数据引用的保留对象及删除生命周期还需纳入额度/清理协议，不能仅按活动文件计量。只有应用切换完成才更新 GUI 后端状态，旧文件清理仍需单独确认。

## 共享存储按成员恢复

- 成员 checkpoint 使用独立提交序号，保留同一共享配置内其他成员的活动根；另一个成员提交成功不会将失败 intent 误判为完成。完整 scope 提交或验证通过的个人 S3 迁移可结清被替代的成员 intent，迁移缺少原有根时拒绝切换。
- 读取配置/扫描源文件前先持久记录待提交范围，避免早期失败后重启把未提交的删除重新补回。恢复按成员跳过未结算范围；单个根的远端缺失/损坏或本地冲突按归属报告，继续恢复其他成员。
- 已结算 intent 移入 `intents/settled/`，保留远端对象追溯信息但不再参与每次状态查询；归档失败不推翻已经提交的活动指针。历史对象的容量与清理协议仍待接入，归档不代表删除。
- 14 项后端回归通过，包含跨成员失败隔离、个人 S3 切换、早期提供方故障重启及保留原有恢复行为。日志 `/tmp/anjian-owner-backend-tests.log`。这些是内部后端测试，尚未接入生产读写。


## 下一轮写入接入的明确边界

- 远程上传之外，浏览器文档协作、评论、分享发布、录制及后台状态写入尚未加入统一准入；异步目录扫描期间仍可能出现这些写入，不能对外宣称全局额度已经严格执行。
- 画板上传的 layout/warnings 和 HTML 上传的诊断元数据已按暂存源树计算、计费并随上传提交。异步录制完成后的衍生文件与状态变化仍属于独立写入，未纳入此远程 PUT 事务。
- 普通文件替换失败的回滚，与跨 source/state 多文件提交遇进程崩溃后的恢复是两个问题；后者仍需要持久事务日志。旧 source/state 备份删除失败留下的资源必须纳入最终计费/恢复状态，不可只吞掉异常并宣称额度已闭合。

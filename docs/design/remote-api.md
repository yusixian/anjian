# Anjian 远程 CLI

状态：实现中。目标是本地 Agent 通过 HTTPS 操作自托管工作台，不依赖 SSH 或官方 Cloud。

## 使用与边界

设备通过 `login` 发起短期配对，在已登录工作台的浏览器中明确批准项目权限。每台设备获得独立、限期、可撤销的凭证。`link` 绑定本地目录与远程项目；`push`、`pull` 明确传输作品；现有 `comment`、`check` 自动使用绑定；`watch` 输出可供 Agent 消费的 JSON 事件。

不增加账号平台、计费、第三方 OAuth、任意服务器命令执行。此阶段不做后台双向目录同步，也不承诺自动唤醒任意 Agent 宿主。监听事件与宿主调度分层。

## 现有基础与选择

`src/cli/server.ts` 原本从本机状态文件取得服务地址及主密钥，评论和检查已经使用 HTTP。`src/server/routes/agent.ts` 提供评论读写与检查逻辑；`src/server/hub.ts` 管理已注册项目。新入口复用这些领域行为，保留现有本地命令。

直接开放主密钥和服务器文件路径最省事，但无法按设备撤销、限制项目，也容易泄露管理权限，故不采用。SSH 可用于运维，但不作为产品接口。采用独立 `/api/remote` 协议，使用项目标识而非磁盘路径。

## 协议与权限

- 配对：`POST /api/remote/auth/device` 返回 deviceCode、userCode、verificationUri、expiresIn、interval；浏览器明确选择允许的已注册项目。短码不能换取 Token，设备秘密不能授权自己。
- 轮询：`POST /api/remote/auth/token` 在批准后一次性返回设备 Token；服务端仅持久化摘要，默认 90 天有效。失败、拒绝、过期有明确状态。
- 管理：`/devices` 展示并撤销设备，`/connect` 批准或拒绝配对。管理操作要求已有工作台身份与同源 POST。CLI logout 撤销当前凭证。
- 项目：`GET /api/remote/projects` 只列出授权且仍注册的项目。设备不能注册任意服务器路径、停止服务器或访问其他项目。
- 作品：`GET/PUT /api/remote/projects/:project/artifacts/:type/:id` 使用文件清单与内容哈希版本。PUT 必须匹配 baseRevision；没有基线只能新建，不能覆盖已有作品。
- 反馈：`POST /api/remote/projects/:project/agent/:type/:id/comments` 与 check 复用现有处理；`GET .../events?cursor=...` 提供持久化游标续接，过旧游标明确返回 410，不能默默跳过。

## 数据完整性

只传作品源码和资源；服务器评论、历史、CRDT 状态、密钥、点目录不进入上传清单。限制 1000 个文件、32 MiB 解码内容，拒绝路径穿越、大小写碰撞、非普通文件及符号链接。完整验证后暂存，再提交；失败恢复原内容。

浏览器文档写入可能尚未落盘。传输前等待文档会话合并和保存，再计算版本；更新通过会话已有合并流程进入网页。客户端 pull 同样检查本地修改，保留用户尚未上传的内容。

凭证与绑定保存在用户配置目录，目录 0700、文件 0600，不写入项目仓库。CLI 对公网只接受 HTTPS，不跟随携带凭证的重定向。浏览器 Cookie 与设备 Bearer 凭证各自适用自己的入口。

## 验收与上线

测试批准/拒绝/过期/撤销、跨项目越权、路径攻击、覆盖冲突、二进制传输、本地兼容和事件续接。浏览器验收设备管理桌面/手机及真实 CLI 授权流程。通过检查后部署到现有 Dokploy，线上验证上传、批注、拉取、撤销及重启后凭证/事件保留。保留旧本地 API，回滚应用不会修改原作品目录布局；新增设备和事件数据独立存储。

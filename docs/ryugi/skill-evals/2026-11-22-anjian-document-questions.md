# 案间文档问答指引验证

日期为 2026-11-22。两名独立 Agent 分别只读 `0.4.0` 和候选版的文档与远程反馈指引。两次使用相同场景，要求在文档内添加带推荐项的发版日期选择及一个开放题，在读者提交后回复确认，并保留提交后的答案。

- 基线使用静态段落和列表表达问题。它找不到原生题目与选项标识，也找不到只回复的任务结果格式。普通批注只能部分满足要求。
- 候选版正确生成两个顶层 `<ask>` 块，保留题目 key 和选项 ID，通过 `questionContext` 读取提交时的题目与答案。它为两个任务分别准备 `{operationId,questionReply}`，复用现有认领和结果命令，并检查 `awaiting_review` 和已保存回复。

## 运行验证

- 类型检查和完整应用测试通过，覆盖 231 个文件的 1,906 项测试。问答测试覆盖 LiteXML、Loro 同步、草稿重启恢复、提交幂等、旧认领失效、回复重放和验收。
- 隔离 Chrome 在 1440×900 保存选择题草稿、重载、提交并撤回，在 390×844 阅读模式完成开放题并看见实际 CLI 回复。随后在反馈面板查看提交快照和回复，再验收。两个视口均无横向溢出或未捕获页面异常。历史视图和匿名公开快照显示题目和选项，页面没有输入控件或私人回答。
- 另一个独立测试文档经 Chrome 明确提交后唤醒真实 Lody 会话。会话首次认领，在同一反馈任务提交独立回复。Chrome 验收后，持久记录为 `accepted`。同步回写没有改动文档源。
- 双语 Changeset 在 `0.4.0` 临时副本生成 `0.5.0` 条目，通过版本一致性检查。

## 评审回归

- 评审修复后跑通 232 个测试文件的 1,912 项测试。最终候选对文档协作、问答 API 和卡片又执行 107 项定向测试。测试覆盖粘贴副本分配新标识、剪切保留原标识、拒绝重复标识的协作保存并保留原文件，以及旧回答使用旧选项标签。
- 最终构建在隔离 Chrome 中复测桌面和手机问答。测试让反馈接口先返回与当前文档不同的题目，确认两个来源一致后页面才启用回答。桌面草稿重载、提交与撤回，手机提交与 CLI 回复均通过。

# 案间作品引用指引验证

两名独立 Agent 分别只读案间 `0.4.0` 和候选版的文档与远程指引。两次使用同一场景，要求在可公开发布的评审稿里引用 HTML 预览和与画板同名的 `proposal` 验收组。

- 基线只能给出通用 `<a href="…">`。指引没有可推导的稳定引用语法，也没有区分同名组与卡片的定位方法。
- 候选正确使用顶层 `<ref type="artboard" … group="proposal" />` 和 `<ref type="html" … />`，仅保存稳定 ID。它要求用预期读者的浏览器权限打开并确认焦点，正确区分公开来源快照和目标的独立分享。

## 运行验证

- 类型检查及应用全量回归通过，覆盖 232 个文件、1,924 项。引用路由测试覆盖精确稳定地址、目录改名、回收站恢复、重复地址、成员访问隔离、验收组状态及分享撤销。
- Chrome 在 1440×900 定位同名验收组所在页，在 390×844 定位另一页同名卡片，两次都按目标范围缩放。HTML 目标重命名后仍能打开，移除后显示引用不可用。
- 匿名来源快照只显示作者填写的文字，浏览器没有发起私有引用查询，DOM 没有目标链接。组件库产物通过禁止固定 Hub API 路径的检查。
- 在 `0.4.0` 临时副本生成 `0.5.0` 中英文更新说明并验证版本一致性。

## 与文档提问的集成验证

- 在同一文档加入提问与三条引用。隔离 Chrome 在桌面和手机分别定位同名组和画板，打开 HTML 预览，并在预览目录移动和移除后得到对应结果。匿名快照保留提问和引用文字，页面没有目标链接或解析请求。
- 独立审查后补测异常焦点标题、同名目录的损坏 ID 及协作更新中的嵌套引用。焦点标题回退到作品标题，有效稳定地址继续可打开，嵌套引用被拒绝后文档原样保留并可继续编辑。

## 原生作品集成后的验证

给 Agent 一条带访问密钥的分镜链接，要求生成文档顶层引用并说明验证方法。更新前，Agent 按指南拒绝生成，因为支持列表只列出文档、HTML 和画板。更新后，同一任务生成了 `<ref type="storyboard" target="A12345678901234567890" label="Launch walkthrough" />`，省略了密钥和查询参数，并说明先运行文档检查，再以预期读者的权限打开。指南保留了公开快照显示引用文字的语义。

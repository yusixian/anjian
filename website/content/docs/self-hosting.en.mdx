title: Self-Hosting
description: Deploy Anjian on your own server with Docker Compose or Dokploy over HTTPS.
---

## Requirements [#prepare-for-deployment]

- A server with Docker Compose and persistent storage
- Two HTTPS domains: one for the main workbench, one for isolated artboard previews

## Two origins [#two-origins]

| Purpose | Container port | Environment variable | Example |
| --- | --- | --- | --- |
| Main workbench, docs, comments & WebSocket | `27319` | `ANJIAN_PUBLIC_ORIGIN` | `https://anjian.example.com` |
| Isolated artboard preview | `27329` | `ANJIAN_BOARD_ORIGIN` | `https://preview.example.net` |

> Set each origin to `https://domain` only (no trailing path). Enable WebSocket proxying on the main domain.

## Docker Compose

```bash title="Terminal · repo root"
export ANJIAN_PUBLIC_ORIGIN=https://anjian.example.com
export ANJIAN_BOARD_ORIGIN=https://preview.example.net
docker compose up --build -d
docker compose logs anjian
```

Ports bind to loopback by default—point Nginx, Caddy, or Traefik at `27319` and `27329`. Data persists in the `anjian-data` volume (`/data/project` and `/data/server`); save the admin access key printed in the startup logs.

## Deploying with Dokploy [#dokploy]

1. Create a Compose app pointing to this repo (build path `/`, Compose file `compose.yaml`).
2. Add `ANJIAN_PUBLIC_ORIGIN` and `ANJIAN_BOARD_ORIGIN` in environment variables.
3. Attach your main domain (`27319`) and preview domain (`27329`) with HTTPS enabled, then deploy.

## GitHub sign-in & friend invites (optional) [#github-sign-in-and-invitations]

Create a GitHub OAuth App (Homepage URL = your main domain, callback = `https://your-main-domain/auth/github/callback`) and set:

```dotenv title="Deployment env (never commit secrets)"
ANJIAN_GITHUB_CLIENT_ID=<OAuth Client ID>
ANJIAN_GITHUB_CLIENT_SECRET=<OAuth Client Secret>
ANJIAN_GITHUB_OWNER_ID=<Admin numeric GitHub user ID>
```

Leave all three blank to use access-key login only (partial config prevents startup). Only the admin and invited members can sign in; the admin key remains available as a fallback.

## Post-deploy check [#check-after-deployment]

Sign in, open an artboard and HTML preview, verify live comments, run a CLI `login` → `link` → `push`, and confirm data survives a container restart.

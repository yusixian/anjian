## 阅读与编辑

文档以富文本呈现，支持标题、列表、表格、代码、图片、公式、Mermaid 图、图表、步骤和嵌入的动态内容。具体内容由作品提供。目录帮助定位章节。

在私有文档中，嵌入的 HTML 会随源文件变化自动刷新。连接恢复时，打开的文档也会加载最新的嵌入内容。

有权限时可在浏览器使用「改字」编辑文本。Agent 也可以修改源文件；保存和协作状态由服务管理。看到「未同步」或「存储额度不足」时，不要刷新或关闭页面，先恢复连接或容量，并等待保存完成。

## 在文字上批注

选择文字或段落后添加评论。评论跟随对应内容，右侧可查看对话、回复与处理状态。原内容删除或大幅改动后，锚点可能失效，此时需要结合上下文确认位置。

让 Agent [读取批注并回复](/docs/agent)，完成后检查修改，再决定是否将评论标为已解决。

在 Hub 运行时恢复文档文件、切换或合并 Git 分支后，打开原文档的「恢复批注」。如果发现工作区带入的人工批注，核对作者和内容，再点「合并这些批注」。

也可以点「导入备份文件」，选择从备份或 Git 导出的 `comments.json`。案间合并讨论，保留原作者、时间和位置。同一个文件可以重新导入。

## 历史对比

打开「历史」，选择时间点或对比范围，查看新增、删除和修改；可只看变更并在各处差异之间跳转。对比期间正文为只读，有新内容时可以更新对比。

历史中的动态内容不运行；媒体资源没有完整历史归档，同一地址的图片可能已经更新。历史对比不能代替文件备份。

## 重跑验收检查

在运行本机 Hub 的机器上，编辑案间服务器目录中的 `verification-checks.json`。默认服务器目录是 `~/.anjian/server`，设置了 `ANJIAN_SERVER_HOME` 时用指定目录。项目填 `pwd -P` 返回的绝对路径，文档填私有链接中 `/document/` 后的稳定 ID。每条命令填可执行文件的绝对路径及其参数。Hub 以该项目目录为工作目录运行命令。

```json
{
  "reports": [
    {
      "project": "/path/to/project",
      "document": "A12345678901234567890",
      "checks": [{ "id": "test", "title": "项目测试", "command": ["/path/to/pnpm", "test"] }]
    }
  ]
}
```

打开这份本机私有文档，点击页头的「验收检查」，选择「重跑」。展开最近结果可以查看输出和 SHA-256。运行历史保存在服务器目录的 `verification-runs/`，原文档内已采集的证据保留。桌面可展开结果面板，手机使用全宽。

自托管时，在需要运行的报告配置中加入 `"allowSelfHosted": true`，然后以站点所有者身份通过自建站点打开报告。只有所有者可以运行检查及查看这段运行历史。使用 Docker 时，配置文件位于容器内的 `/data/server/verification-checks.json`，项目和可执行文件也填容器内的绝对路径。

## 文档源文件

文档使用 `.anjian/artifacts/document/<id>/doc.xml`（LiteXML）与 `assets/`。这不是直接把 Markdown 文件改名成 XML。让 Agent 先执行 `anjian skills get artifacts --reference document.md`。

服务器会为块补齐 ID；编辑前重新读取文件，保留已有块 ID，避免批注丢失定位。不要从旧副本覆盖整份文档，也不要编辑服务器管理的 `comments.json`。

这里的 `anjian` 指构建后的 CLI 或已有包装器；可执行入口与内置 Skill 的发现方式见[批注与 Agent](/docs/agent)。

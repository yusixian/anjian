---
title: 用画板批注推进文档站设计
description: 从查看设计稿、留下具体意见，到让 Agent 读取评论并修改。
---

这次案间文档站的设计过程，本身就是一个使用案例：先让 Agent 制作画板，在浏览器里指出需要修改的位置，再回到会话要求 Agent 读取批注并修改。

## 1. 在画板上指出问题

打开设计稿，使用评论工具，在具体元素或区域留下意见。例如搜索图标不清晰、顶栏图标太小、文字冗余，或者首页展示需要调整。评论保留在作品旁，Agent 可以读取评论内容和定位信息。

![案间画板展示文档站的深浅色设计稿；右侧四条评论分别指出搜索图标、图标大小、多余文字和首页展示的问题。](/use-cases/artboard-comments.png)

## 2. 回到会话，让 Agent 读取并修改

把作品链接发给已接入案间的 Agent，并说明「看看我的所有评论，修复一下」。Agent 读取批注，拉取作品，修改后上传并检查，再在原评论中回复结果。

![Lody 会话中，用户先要求通过案间制作设计稿，随后发送画板链接要求处理评论；Agent 开始读取全部批注。](/use-cases/agent-feedback.png)

截图来自用户提供的实际过程，记录的是修改前的画板与开始处理反馈的会话，不是修改完成的验收截图。截图里的代码改动列表也不代表文档站已部署。

## 3. 查看新版，再决定下一步

回到原作品检查修改。还需调整时继续批注；确认满意后再解决评论。评论和事件监听本身不会自动唤醒 Agent，本例由用户回到会话发出处理请求。

[查看此案例的公开作品](https://anjian.cosine.ren/s/eTPVcN0J7yUd7-a1Gu9fv0FSsKRP3b7fUGoGqyfKfzA)

公开链接是只读快照，访客不能在其中新增批注。上述评论流程发生在有权限的作品工作台中；更新原稿后，需要主动更新分享才会改变公开版本。

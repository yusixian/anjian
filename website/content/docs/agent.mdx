## 读取内置 Skill

先按[本机使用](/docs/local)构建 CLI。构建产物已包含完整 Skill，作品项目无需放置源码。下文的 `anjian` 指已有包装器，或 `node /绝对路径/anjian/artifacts/dist/cli.cjs`。

```bash title="CLI · 读取接入指引"
anjian --help
anjian skills list
anjian skills get artifacts
anjian skills get artifacts --reference remote.md
```

`skills list` 列出内嵌的参考文件与示例。`skills get` 完整输出 Markdown，管道中也一样；加 `--json` 可读取结构化输出。相对链接用 `--reference` 配合列表中的名称继续读取。读取帮助或 Skill 不启动服务、打开浏览器、订阅批注或写入授权。

宿主需要显式阅读这些指引，或通过其支持的方式加载 Skill。内嵌 Skill 不等于宿主自动加载或后台调度。有源码时，也可选用 `skills/artifacts/SKILL.md` 及同目录参考文件。

## 配置项目入口

在实际作品项目的 `AGENTS.md`（或宿主对应的项目指引）记录入口。只记录路径与服务器地址，不记录访问密钥或设备 token。

```text title="项目接入说明示例"
CLI：node /绝对路径/anjian/artifacts/dist/cli.cjs
处理案间作品前，用上述 CLI 执行 skills get artifacts。
远程任务继续执行 skills get artifacts --reference remote.md。
作品项目：/绝对路径/作品项目（所有命令传 --project-dir）
服务器：https://你的案间域名
客户端配置：~/.anjian/client/
先用 remote status --json 核验；有效绑定直接复用。
未授权时发起 login，保持进程等待用户在浏览器批准。
随后 link 绑定项目，并回读 remote status --json。
```

已有包装器时记录包装器路径，复用固定的项目与客户端配置。自定义 `ANJIAN_CLIENT_HOME` 时所有命令保持一致。配对与项目选择参见[设备与 CLI](/docs/remote-cli)。不同机器需要分别授权，不要复制其他项目的凭证。

## 一轮反馈怎么处理

1. 在有权限的作品工作台里添加批注。
2. 回到 Agent 会话，发送作品链接和处理要求。
3. Agent 读取完整批注；远程作品先安全拉取，再修改。
4. 上传并检查，在浏览器验证相关结果，再回复原线程。
5. 由你确认修改；只有你要求或明确确认解决后才关闭评论。

```bash title="CLI · 在已绑定项目中"
anjian comment list --artifact document/plan --all --json
anjian pull --artifact document/plan
# 编辑源文件后：
anjian push --artifact document/plan
anjian check --artifact document/plan
anjian comment reply --artifact document/plan --thread "实际线程ID" --text "已修改"
```

这里的 `anjian` 指本仓库构建的 CLI，可用 `node /绝对路径/anjian/artifacts/dist/cli.cjs` 替代。在实际作品项目目录执行，或始终传入相同的 `--project-dir`。

## GitHub Copilot CLI

先准备可用的案间 CLI。用案间源码目录下的完整 `skills/artifacts/` 安装项目级 Skill。在作品项目根目录执行以下命令，并替换源码路径。

```bash
mkdir -p .github/skills/artifacts
cp -R /绝对路径/anjian/skills/artifacts/. .github/skills/artifacts/
copilot skill list
```

确认 `artifacts` 出现在项目 Skill 列表中。把案间 CLI 的绝对路径或包装器记进上文的项目指引。如果用 `copilot -p`，先在独立终端运行本地 Hub，再从作品项目启动 Copilot。

```bash
anjian start --project-dir "$PWD" --no-open --foreground
```

在 Copilot 会话里请它使用 `artifacts` Skill 创建 `document/plan` 并给出预览链接。在浏览器打开链接并提交批注，然后回到原会话，请它运行以下命令读回新批注。要查看全部批注，加上 `--all`。

```bash
anjian comment list --project-dir "$PWD" --artifact document/plan --json
```

## DeepSeek Harness

先构建案间，并准备 DeepSeek Harness `0.2.2-rc.5` 或兼容版本。用官方 `dsh` 命令向现有 profile 安装案间插件。下方以 `web` 为例。

```bash
ANJIAN_SOURCE="/绝对路径/anjian"
dsh plugin --profile web add "file:$ANJIAN_SOURCE/integrations/deepseek"
```

在实际作品项目根目录安装完整的案间 Skill。启动 DSH 时让插件使用构建好的案间。

```bash
mkdir -p .dsh/skills/artifacts
cp -R "$ANJIAN_SOURCE/skills/artifacts/." .dsh/skills/artifacts/
ANJIAN_DSH_APP="$ANJIAN_SOURCE/skills/artifacts/app" dsh --profile web
```

在案间本机 Hub 打开文档或画板，并在希望接收反馈的 DSH 会话输入 `/anjian watch document/plan`。提交浏览器批注后，该会话会收到通知和读取命令。可用 `/artifacts` 打开案间 Skill。通知发出后批注仍为未读，读取才会推进该会话的回执。

用 `/anjian status` 查看订阅，用 `/anjian unwatch document/plan` 停止订阅。会话结束或切换工作目录后需要重新订阅。

## 自定义 Agent 宿主

让本机 Hub 把文档批注和画板反馈交给你指定的程序。先启动案间，在你的本机配置目录写一个 JSON 文件。以下示例将收到的事件打印到终端。把 `command` 的第一个元素换成可执行文件的绝对路径，再按需替换后续参数。

```json
{
  "artifacts": ["document/plan", "artboard/design"],
  "command": ["/absolute/path/to/node", "-e", "process.stdin.pipe(process.stderr)"],
  "host": "review-desk",
  "name": "Review Desk",
  "session": "terminal:123"
}
```

在作品项目中运行 `anjian feedback-host --config /绝对路径/host.json --json`，保持终端或父进程运行。每次投递会启动配置的程序，把一行 JSON 写入它的标准输入。数据包含 `type`、`host`、`name`、`session`、`projectDir` 和 `artifact`。画板提交也包含轮次和撤回状态。适配器可运行以下命令读回批注，并用同一个会话记录已读。加 `--peek` 可只查看。

```bash
anjian comment list --artifact document/plan --session review-desk:terminal:123 --json
```

在监听进程的标准输入发送 `{"action":"unsubscribe","artifact":"document/plan"}` 可以移除一个作品。发送同格式的 `subscribe` 可重新监听。Hub 按该监听连接当前的订阅清单发送事件，断线重连时恢复仍在清单里的作品。关闭标准输入或按 Ctrl+C 会停止这次监听。永久移除时更新或删除自己的配置文件。

## 事件与自动处理

`anjian watch --json` 输出事件，宿主需要自己订阅并调度任务。收到事件后再读取评论或拉取作品；事件输出不等于 Agent 已自动醒来处理。首次监听不重放全部历史评论，需要历史时使用 `comment list --all`。

在本地画板里选好方案并点「提交」后，已订阅的 Codex、Pi 或 Antigravity 会话可直接收到该轮的答案和批注位置。通知会标明沿用的推荐项，并保留读取完整反馈的命令。收到通知后，批注继续保持原有已读状态。

## 把文档答案发给本地 Agent

先让 Codex、Pi 或 Antigravity 在当前会话里用案间打开该文档，具体入口见[评审流程](/docs/review-workflows)。使用 DeepSeek Harness 时，在要接收答案的会话输入 `/anjian watch document/plan`，替换成你的文档 ID。在问答卡中填写或选择答案，选定会话后点「发送给…」。同一个文档有多个会话时，用列表中的宿主名和会话末尾标识区分。Agent 会直接收到题目、答案和文档修订。

「等待本地 Agent 接收」时，如果仍显示「撤回提交」，可以撤回并保留草稿。「已发送给本地 Agent」表示宿主已接收消息。需要在文档里等待 Agent 回传答复时，选择已连接的 Lody 会话。

通知会附上只读命令。答案超过消息长度上限时，Agent 可在原作品工作区执行该命令读取全文。文档已经改版时，请确认新修订后重新提交。

## 换一个 Agent 接手

给接手的 Agent：作品链接、作品标识、项目目录、CLI 入口、Skill 读取命令和具体修改范围。让前一个 Agent 先完成上传，避免同时编辑同一作品。公开分享链接只用于查看，不能代替编辑授权。

## 从作品页启动 Codex 规划任务

在运行案间 Hub 的主机上安装并登录 Codex CLI，让 Hub 服务账号可以通过 `PATH` 找到 `codex`。用 `ANJIAN_CODEX_TASKS=1` 启动或重启 Hub。

以 Hub 所有者身份打开作品，展开「Codex 任务」，填写首轮提示并启动规划任务。Codex 在该作品的项目目录内以只读方式运行。同一项目的其他作品页也会显示待回复的问题。在手机上可从作品页顶部打开同一面板。输入每个问题的答案，再选择「发送回复」。

这个入口管理案间新建的会话。已有的 Codex 桌面会话仍从 Codex 操作。Hub 重启后，旧连接里的待答问题会清除。

打开面板里的「最近任务」可查看本次 Hub 运行期间的任务状态和 Codex 返回的方案。需要保留方案时，可从任务详情复制内容。

如果想用独立文档记录首轮提示，启动前勾选「创建任务文档」。文档保存在当前作品所属项目。启动后点击「打开任务文档」，也可以从最近任务打开同一份文档。

要从作品页回复已有的终端会话，在 Hub 主机上显式启动一个共享 Codex App Server，并用同一服务打开 Codex 终端。准备一个仅服务账号可读的令牌文件，内容是一条随机令牌。示例使用回环地址：

```bash
codex app-server --listen ws://127.0.0.1:8765 --ws-auth capability-token --ws-token-file /path/to/token
```

在 Hub 的环境中设置 `ANJIAN_CODEX_SHARED_URL=ws://127.0.0.1:8765` 和 `ANJIAN_CODEX_SHARED_TOKEN_FILE=/path/to/token`，然后重启 Hub。设置后，从案间启动的新任务也使用这个 App Server。在终端中让 `CODEX_SHARED_TOKEN` 保存同一令牌，并在作品项目目录运行：

```bash
codex --remote ws://127.0.0.1:8765 --remote-auth-token-env CODEX_SHARED_TOKEN
```

会话运行后，在同一项目的作品页展开「Codex 任务」，填写会话 ID 并选择「接入已有会话」。已有待答问题会出现在面板。Hub 断开后，只要 App Server 上的会话仍在运行，可以再次输入同一 ID 接入。此前通过独立进程启动的会话，需要继续在原 Codex 客户端操作。

Hub 与 Codex App Server 也可以在同一台 Linux 或 macOS 主机上通过 Unix socket 连接。由运行 Hub 的同一用户在私有目录创建 socket，并将 `ANJIAN_CODEX_SHARED_SOCKET` 设为该 socket 的绝对路径。使用此方式时无需设置 WebSocket 地址与令牌文件。

```bash
codex app-server --listen unix:///path/to/private/codex.sock
codex --remote unix:///path/to/private/codex.sock
```

分别在两个终端运行这两条命令。等待会话需要输入后，从作品页使用同一会话 ID 接入。

如果接入的终端会话在等命令审批，「Codex 任务」会显示命令、工作目录与 Codex 提供的理由。核对会话与命令后，可从面板执行当前请求提供的「仅允许这一次」「拒绝命令」或「取消本轮」。需要修改长期规则或处理额外权限的请求，请回到 Codex。

## Shared quotas

Admins set a total shared budget under **Storage → Instance shared** and assign per-member limits. Usage includes artifacts, history, collaboration data, trash, and share snapshots. When quota is full, keep unsynced document tabs open while freeing space—they retry automatically.

## Connecting S3 [#configure-shared-or-personal-s3]

Admins can configure shared S3, and members can bind their own bucket under **My S3** (stopping shared quota usage):

1. Enter a public HTTPS Endpoint, Bucket, Region, optional prefix, and scoped credentials (check path-style addressing for most self-hosted S3 providers). Private endpoints and self-signed certs aren't supported.
2. Click **Save configuration**, then **Test connection** (writes, verifies, and deletes a tiny test object). Neither step moves files.

## Migrating & activating [#migrate-and-enable]

Follow **Prepare migration** → **Copy and verify** → confirm and click **Activate S3**. Active storage shows as **S3 (server cache)**: files are served via server cache and synced to S3 while original server files remain intact.

## Sync failures & recovery [#failure-and-recovery]

If sync fails, local edits stay safe—click **Retry sync**. If a restart asks for storage recovery, verify server files are present and follow the restore prompt.

## Server disk [#server-disks]

Admins see filesystem capacity and free space on **Instance shared** (including OS and other apps, refreshed every 60 seconds).

## What to back up [#what-to-back-up]

Members, invites, encrypted credentials, and storage bindings still live on the server even with S3 enabled. Back up the full `/data` volume on Docker, or `.anjian/` and `~/.anjian/server/` in local mode.

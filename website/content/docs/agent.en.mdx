## Read the built-in Skill

Build the CLI using the [local guide](/docs/local). The built CLI includes the complete Skill; your artifact project does not need a source checkout. In the commands below, `anjian` means your existing wrapper or `node /absolute/path/anjian/artifacts/dist/cli.cjs`.

```bash title="CLI · Read integration guidance"
anjian --help
anjian skills list
anjian skills get artifacts
anjian skills get artifacts --reference remote.md
```

`skills list` lists the bundled references and examples. `skills get` prints complete Markdown, including when piped; add `--json` for structured output. Follow relative links with `--reference` using a name from the list. Reading help or Skills does not start a service, open a browser, subscribe to comments, or write authorization.

The host must explicitly read these instructions or load the Skill through its supported mechanism. A built-in Skill does not mean automatic host loading or background scheduling. With a source checkout, `skills/artifacts/SKILL.md` and its sibling references remain optional entry points.

## Configure a project entry point

Record the entry point in the actual artifact project's `AGENTS.md` or equivalent host instructions. Record paths and the server address, never access keys or device tokens.

```text title="Example project integration instructions"
CLI: node /absolute/path/anjian/artifacts/dist/cli.cjs
Before working on Anjian artifacts, run skills get artifacts using this CLI.
For remote tasks, also run skills get artifacts --reference remote.md.
Artifact project: /absolute/path/to/artifact-project (pass --project-dir to every command)
Server: https://anjian.example.com
Client configuration: ~/.anjian/client/
Verify with remote status --json first; reuse a valid binding.
If unauthorized, initiate login and keep it running while the user approves in the browser.
Then link the project and read back remote status --json.
```

If a wrapper exists, record its path and reuse its fixed project and client configuration. Keep a custom `ANJIAN_CLIENT_HOME` consistent across commands. See [Devices and CLI](/docs/remote-cli) for pairing and project selection. Authorize each machine separately; do not copy credentials from another project.

## Process a round of feedback

1. Add comments in an artifact workspace you can access.
2. Return to the Agent conversation and send the artifact link and your request.
3. The Agent reads all comments and safely pulls remote artifacts before editing.
4. Upload and check, verify the relevant results in the browser, then reply in the original thread.
5. You review the changes. Close comments only when you request or explicitly confirm resolution.

```bash title="CLI · In a linked project"
anjian comment list --artifact document/plan --all --json
anjian pull --artifact document/plan
# After editing the source:
anjian push --artifact document/plan
anjian check --artifact document/plan
anjian comment reply --artifact document/plan --thread "actual-thread-ID" --text "Updated"
```

Here, `anjian` means the CLI built from this repository. You can replace it with `node /absolute/path/anjian/artifacts/dist/cli.cjs`. Run in the actual artifact project, or consistently pass the same `--project-dir`.

## GitHub Copilot CLI

Prepare a working Anjian CLI first. Install the complete `skills/artifacts/` directory from the Anjian source checkout as a project Skill. From your artifact project's root, run these commands with your own source path.

```bash
mkdir -p .github/skills/artifacts
cp -R /absolute/path/anjian/skills/artifacts/. .github/skills/artifacts/
copilot skill list
```

Confirm that `artifacts` appears in the project Skill list. Record the absolute path to the Anjian CLI or your wrapper in the project instructions above. When using `copilot -p`, start the local Hub in a separate terminal before starting Copilot from the artifact project.

```bash
anjian start --project-dir "$PWD" --no-open --foreground
```

Ask Copilot to use the `artifacts` Skill to create `document/plan` and give you its preview link. Open it in a browser and submit a comment. Return to the original session and ask Copilot to run the following command to read new comments. Add `--all` to see the full comment history.

```bash
anjian comment list --project-dir "$PWD" --artifact document/plan --json
```

## DeepSeek Harness

Build Anjian and use DeepSeek Harness `0.2.2-rc.5` or a compatible release. Install the Anjian plugin into an existing profile with the official `dsh` command. This example uses `web`.

```bash
ANJIAN_SOURCE="/absolute/path/to/anjian"
dsh plugin --profile web add "file:$ANJIAN_SOURCE/integrations/deepseek"
```

Install the complete Anjian Skill in the artifact project. Point the plugin to the built Anjian checkout when starting DeepSeek Harness.

```bash
mkdir -p .dsh/skills/artifacts
cp -R "$ANJIAN_SOURCE/skills/artifacts/." .dsh/skills/artifacts/
ANJIAN_DSH_APP="$ANJIAN_SOURCE/skills/artifacts/app" dsh --profile web
```

Open a document or artboard in the local Anjian Hub, then enter `/anjian watch document/plan` in the DeepSeek session that should receive feedback. After someone adds a browser comment, the session receives a notification and a command to read it. Use `/artifacts` to open the Anjian Skill. Comments stay unread until the command reads them for the specified session.

Use `/anjian status` to list subscriptions or `/anjian unwatch document/plan` to stop one. Subscribe again after ending the session or changing its working directory.

## Custom Agent hosts

Send local document comments and artboard feedback to a program you choose. Start Anjian and save a JSON file in your local configuration directory. This example prints each event to the terminal. Use an absolute executable path as the first element of `command`, followed by its arguments.

```json
{
  "artifacts": ["document/plan", "artboard/design"],
  "command": ["/absolute/path/to/node", "-e", "process.stdin.pipe(process.stderr)"],
  "host": "review-desk",
  "name": "Review Desk",
  "session": "terminal:123"
}
```

From the artifact project, run `anjian feedback-host --config /absolute/path/host.json --json` and keep the terminal or parent process running. Each delivery starts the configured program and sends one JSON line to its standard input. The event includes `type`, `host`, `name`, `session`, `projectDir`, and `artifact`. Artboard submissions also identify the round and whether it was withdrawn. The adapter can use the following command to read comments and record them for the same session. Add `--peek` to inspect them without recording a read.

```bash
anjian comment list --artifact document/plan --session review-desk:terminal:123 --json
```

Send `{"action":"unsubscribe","artifact":"document/plan"}` to the watcher's standard input to remove one artifact. Use the same format with `subscribe` to listen again. The Hub filters events for this connection and restores its current subscriptions when the listener reconnects. Close standard input or press Ctrl+C to stop listening. Edit or remove your configuration file to make the change permanent.

## Events and automation

`anjian watch --json` emits events; the host must subscribe and schedule tasks itself. After an event, read comments or pull the artifact. Event output does not mean an Agent has automatically started working. The first watch does not replay all historical comments; use `comment list --all` when you need history.

After choosing options on a local artboard, select **Submit**. A subscribed Codex, Pi, or Antigravity session receives the round’s answers and comment locations. The message identifies defaults from recommendations and includes the command for reading full feedback. Delivery preserves the existing read status.

## Send a document answer to a local Agent

Have Codex, Pi, or Antigravity open the document in its current session using the commands in [Review workflows](/docs/review-workflows). In DeepSeek Harness, enter `/anjian watch document/plan` in the session that should receive answers, using your document ID. Fill in or select an answer, choose the session, then select **Send to…**. Use the host name and session suffix to distinguish sessions on the same document. The Agent receives the question, answer, and document revision.

While the card shows **Waiting for the local Agent**, select **Withdraw submission** if the button is available. This keeps the answer as a draft. **Sent to the local Agent** means the host received the message. Choose a connected Lody session when you want the Agent’s reply to appear in the document.

The notification includes a read-only command. When the answer exceeds the message limit, the Agent can run that command in the original worktree to read the full answer. If the document has changed, review the new revision and submit the answer again.

## Hand over to another Agent

Give the next Agent the artifact link, artifact ID, project directory, CLI entry point, Skill reading command, and precise editing scope. Have the previous Agent finish uploading first to avoid concurrent edits. A public share is for viewing and does not grant editing permission.

## Start a Codex planning task from an artifact

Install and sign in to the Codex CLI on the Hub host. Make sure the Hub service account can find `codex` on its `PATH`. Start or restart the Hub with `ANJIAN_CODEX_TASKS=1`.

Open an artifact as the Hub owner, expand **Codex tasks**, enter the first prompt, and start a planning task. Codex runs in the artifact's project directory with read-only access. Pending questions also appear on the other artifacts in the same project. On a phone, open the panel near the top of the artifact page. Answer each question, then select **Send reply**.

This panel manages sessions created by Anjian. Open existing desktop sessions in Codex. Restarting the Hub clears questions from the previous connection.

Open **Recent tasks** in the panel to see task status and plans returned by Codex during the current Hub run. To keep a plan, copy it from the task details.

To keep the first prompt in a separate document, select **Create a task document** before starting. Anjian saves it in the current artifact's project. Select **Open task document** after starting, or open the same document from the recent task.

To answer an existing terminal session from an artifact, explicitly start a shared Codex App Server on the Hub host and open the Codex TUI against that same server. Create a file containing one random token, readable only by the service account. This example uses a loopback address:

```bash
codex app-server --listen ws://127.0.0.1:8765 --ws-auth capability-token --ws-token-file /path/to/token
```

Set `ANJIAN_CODEX_SHARED_URL=ws://127.0.0.1:8765` and `ANJIAN_CODEX_SHARED_TOKEN_FILE=/path/to/token` in the Hub environment, then restart the Hub. New tasks started from Anjian also use this App Server. In the terminal, set `CODEX_SHARED_TOKEN` to the same token and run this command in the artifact project directory:

```bash
codex --remote ws://127.0.0.1:8765 --remote-auth-token-env CODEX_SHARED_TOKEN
```

While the session is active, open **Codex tasks** on an artifact in the same project, enter the session ID, and select **Connect existing session**. Any pending question appears in the panel. If the Hub disconnects, reconnect with the same ID while the session is still running on the App Server. Continue using the original Codex client for sessions started in independent processes.

The Hub and Codex App Server can also connect through a Unix socket on the same Linux or macOS host. Run both as the same user, create the socket in a private directory, and set `ANJIAN_CODEX_SHARED_SOCKET` to its absolute path. Leave the WebSocket URL and token file unset when using the socket.

```bash
codex app-server --listen unix:///path/to/private/codex.sock
codex --remote unix:///path/to/private/codex.sock
```

Run these commands in separate terminals. Once the session needs input, connect it from the artifact page using the same session ID.

When a connected terminal session is waiting for command approval, **Codex tasks** shows the command, working directory, and any reason supplied by Codex. Check the session and command, then choose **Allow once**, **Decline command**, or **Cancel turn** as offered by the request. Use Codex for changes to persistent rules.

For additional permission requests from a connected session, check the requested paths and network access in **Codex tasks**. Select only the permissions needed, then choose **Grant selected for this turn**. To continue without granting anything, choose **Deny all permissions**. Use Codex for permission patterns that cannot be selected in the panel.
